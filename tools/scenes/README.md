# ภาพจำลองเหตุการณ์ 2 มิติ (scenes)

ภาพประกอบเคส INTL หนึ่งเคสต่อหนึ่งรายการใน `app/data/scenes.json` (คีย์ = id เคส)
`app/scene.js` วาดเป็น SVG ตอนเปิดเคส ภาพเป็นภาพประกอบ **ไม่ตามมาตราส่วน**
ตัวอย่างที่ผ่านการตรวจแล้ว: INTL-0183 (มุมบน+ข้าง), INTL-0150 (ข้าง+หน้า), INTL-0179 (ข้าง+มุมบน)

## กฎที่ห้ามละเมิด

1. **ห้ามแต่งข้อเท็จจริง** ตัวเลข ลำดับเหตุการณ์ ระดับความแน่นอน และใครทำอะไร ต้องตรงกับ `summary` ของเคส
   ถ้ารายงานไม่บอกค่าใด อย่าเดา ใช้ `dim` ที่มี `"unknown": true` (เส้นประ + "?") หรือไม่ใส่ตัวเลขเลย
2. ตำแหน่ง/ทิศ/ผังที่ไม่ได้มาจากรายงาน (เช่นผังท่าเรือ ทิศสายไฟ) วาดเป็นหลักการได้ แต่ต้องใส่ `note`
   เช่น `"note": "ผังสนามเป็นภาพแสดงหลักการ ไม่ใช่ผังจริง"`
3. หน่วย: **ฟุต นอต ไมล์ ไมล์ทะเล ฟุต/นาที** เท่านั้น (มม. °C กก. ลิตร ปอนด์ ใช้ได้ตามต้นฉบับ) ห้าม เมตร/กม./m/km
   ตัวเลขให้ใช้ตามที่ `summary` เขียนไว้แล้ว (แปลงหน่วยแล้ว) ห้ามแปลงเองใหม่
4. ไม่มีชื่อบุคคล ไม่มีอักษรญี่ปุ่น/จีน (ป้าย 推定 ฯลฯ ใน summary ให้เขียนเป็นไทย เช่น "เกือบแน่ว่า…" "น่าจะ…" หรือไม่ต้องใส่)
5. ภาษาไทย คำศัพท์อังกฤษใช้ตามที่ summary ใช้ (Hover, Collective, Settling with Power, Autorotation, Flare ฯลฯ)

## รูปแบบสเปก

```json
"INTL-0000": {
  "panels": [ { "view": "side", "h": 210, "bg": null, "night": false, "cap": "คำบรรยายสั้น", "el": [ … ] } ],
  "steps":  [ { "n": "1", "ph": "normal", "text": "…" } ],
  "note": "ไม่บังคับ"
}
```

- `panels` 1–3 ภาพ (ส่วนใหญ่ 1–2) · `view`: `side` (ด้านข้าง เห็นความสูง) · `top` (มุมบน เห็นเส้นทาง/ผัง) · `front` (ด้านหน้า เห็นความกว้าง/การเอียง)
- กรอบภาพกว้าง **400** สูง `h` 120–300 (ปกติ 160–220) แกน y ชี้**ลง** (y=0 คือบนสุด)
- `bg`: ไม่ใส่ = ท้องฟ้าไล่สี (ใช้กับ side/front) · มุมบนใส่พื้นเช่น `grass` `paddy` `sea` `desert` `city` `forest` `snow` `runway` `concrete`
- `night: true` = ฉากกลางคืน (ใช้เมื่อรายงานบอกว่ากลางคืน)
- `cap` ≤ 60 ตัวอักษร บอกว่าภาพนี้แสดงอะไร
- `steps` 3–6 ขั้น เรียงตามเวลา แต่ละขั้น ≤ 160 ตัวอักษร (เขียนกระชับ 1–2 วลี)
  `ph`: `normal` ปกติ (เทา) · `warn` เริ่มผิดปกติ (ส้ม) · `danger` อันตราย/ชน (แดง) · `info` ข้อมูลประกอบ (น้ำเงิน)
- ใส่ `mark` (วงกลมเลข) ในภาพตรงจุดที่ขั้นนั้นเกิด เลขต้องมีอยู่ใน `steps` ขั้นที่เกิดก่อนฉากเริ่มไม่ต้องมีหมุดก็ได้

## ชนิดองค์ประกอบ (`t`) — ฟิลด์บังคับ (ไม่บังคับ)

วาดตามลำดับใน `el` ตัวหลังทับตัวก่อน: **พื้น/ภูเขา → สิ่งกีดขวาง → เส้นทาง → อากาศยาน → burst → ป้าย → หมุด**

| t | ฟิลด์ | หมายเหตุ |
|---|---|---|
| ground | kind y (x1 x2) | พื้นเต็มแถบจาก y ลงล่าง kind: grass paddy field hill mountain snow sea water lake desert sand city runway forest rock concrete |
| hill | kind pts | แนวสันเขา `[[x,y],…]` เติมลงถึงขอบล่าง (kind hill/forest จะโปร่ง) |
| area | kind pts | รูปหลายเหลี่ยมปิด (มุมบน: ทะเลสาบ ป่า ลาน) |
| road / river | pts (w) | เส้นหนา |
| heli | x y (s rot type view state flip) | type `light` (R44, AS350, H135 เล็ก) `medium` (ค่าเริ่ม S-70/H225/AW139) `tandem` (CH-47) หัวชี้ +x · flip=true หัวชี้ซ้าย · rot องศา (บวก = ก้มหัวลงเมื่อหัวชี้ขวา) · state `normal` `ghost` (จาง = ตำแหน่งก่อนหน้า) `crash` (สีเข้ม ใบพัดหัก) · view ทับ view ของภาพได้ |
| plane | x y (s rot view state flip) | เครื่องบินปีกตรึง |
| tower | x y h | เสาโครงเหล็ก (y = ฐาน) |
| pole | x y h | เสาไฟ |
| wire | pts (sag hit) | สายไฟ hit=true = เส้นแดง (จุดที่ชน) |
| tree | x y (h) / trees x1 x2 y (h n) | ต้นไม้/แนวต้นไม้ (y = โคน) |
| building | x y w h | y = ฐาน |
| ship | x y w (deck) | deck=false ไม่มีลานจอด |
| rig | x y (s) | แท่นขุดเจาะ (y = ระดับน้ำ) |
| pad | x y (w) | ลานจอด H (มุมบน = วงกลม) |
| runway | x1 x2 y · มุมบน x y w h (rot) | ทางวิ่ง (มุมบนไม่ต้องมี x1 x2) |
| person / vehicle | x y (flip) | คน/รถ (y = พื้น) |
| box | x y w h (text) | สี่เหลี่ยมทั่วไป (กำแพง คันถนน ภูเขาน้ำแข็ง ฯลฯ) |
| cloud | x y w (h) | ก้อนเมฆ |
| fog | y1 y2 (x1 x2) | แถบหมอก/เมฆต่ำ/ฝน |
| burst | x y (r) | จุดชน/ระเบิด |
| line | pts (color dash w) | เส้นทั่วไป color = normal/warn/danger/info/muted หรือ hex (สีอื่นถือว่าผิด) |
| path | pts (ph dash arrow smooth) | เส้นทางบิน มีหัวลูกศร (arrow=false ไม่มี) smooth=false เส้นตรง |
| mark | n x y (ph) | หมุดเลขขั้น รัศมี ~10 |
| label | x y text (anchor tone size) | ป้ายข้อความ size ปกติ 14 (ต่ำสุด 12) `\n` ขึ้นบรรทัด anchor start/middle/end tone muted/warn/bad/info |
| dim | x1 y1 x2 y2 text (unknown side) | เส้นวัดระยะ text "" ได้แล้วใช้ label แยกเมื่อพื้นที่แคบ |
| wind | x y (to text) | ลูกศรลม to = มุมบนจอ 0 ขวา 90 ลง 180 ซ้าย 270 ขึ้น · text อยู่กึ่งกลางใต้ลูกศร (y+26 size 13) อย่าวางชิดขอบ |
| north | x y | เข็มทิศเหนือ (มุมบน) |

### ขนาดอากาศยานที่ s=1 (หน่วยของภาพ, หัวชี้ขวา)

- ด้านข้าง: light x −41..28 y −16..12 · medium x −51..34 y −18..12 · tandem x −60..56 y −22..13 · plane x −36..33 y −14..5
- มุมบน: medium x −46..34 จานใบพัดรัศมี 32 · light = medium × 0.8
- ด้านหน้า: ใบพัดกว้าง x ±38 ที่ y −16
- ใช้ s 0.7–1.2 เป็นหลัก

## เคล็ดลับให้ภาพอ่านง่าย

- ภาพเดียวที่ชัดดีกว่าสามภาพที่แน่น เลือกมุมที่อธิบาย "จุดพลิก" ของเหตุการณ์ได้ดีที่สุด
  เช่น ชนสายไฟ/ภูมิประเทศ/ร่อนลง → ด้านข้าง · หลงทิศ/เลี้ยว/บินชนกัน/ผังลานจอด → มุมบน · เอียงตกข้าง (Dynamic Rollover) ใบพัดฟาดสิ่งกีดขวางด้านข้าง → ด้านหน้า
- ป้ายข้อความห่างจากอากาศยาน หมุด burst และป้ายอื่น ≥ 6 หน่วย อย่าวางตัวอักษรชิดขอบ (เหลือ ≥ 6)
  ความกว้างโดยประมาณ = จำนวนตัวอักษร (ไม่นับสระบน/ล่าง วรรณยุกต์) × size × 0.6
- ป้ายในภาพสั้น (≤ 20 ตัว/บรรทัด) รายละเอียดยาวไว้ใน `steps`
- ใช้ `state: "ghost"` + `path` เพื่อแสดงการเคลื่อนที่จากตำแหน่งก่อนไปหลัง
- ลำดับ ph ของ steps ควรไล่ normal → warn → danger ตามเรื่องจริง

## ตรวจและดูภาพ

```bash
node tools/scenes/cases.mjs INTL-0001 INTL-0002          # อ่านเนื้อหาเคส
node tools/scenes/check.mjs <file.json>                    # ตรวจ (exit 1 ถ้ามี "ผิด")
node tools/scenes/check.mjs <file.json> --ids INTL-0001 --shot <dir> --port 9341   # ถ่ายภาพ <dir>/<id>.png
```

- "ผิด" ต้องเป็น 0 ทุกเคส · "ควรดู" เรื่องตัวอักษรทับ/ล้นให้แก้ เว้นแต่ดูภาพแล้วไม่ทับจริง
- "ขั้น N ไม่มีหมุดในภาพ" ยอมรับได้ถ้าขั้นนั้นเกิดนอกฉาก
- `--shot` ใช้ Chrome headless ถ่ายภาพที่ความกว้างการ์ด 520px (ใกล้จอมือถือ) ให้เปิด PNG ดูด้วยตาทุกครั้งก่อนส่ง
